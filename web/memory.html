Why did memory return the wrong city?

Ada lives in Berlin and plans to move to Paris on January 10. Asked where she lives on January 5, the original program already answers Paris. It should still answer Berlin.

Start here / the input and the mistake

Two facts. One date-sensitive question.

The Python memory program receives structured JSON events: save a fact about Ada’s account, then answer a query using saved facts. These are authored test inputs, not facts extracted from a chat.

  1. January 1, 2026 · save a fact

    The current city is Berlin.

    This fact is valid from January 1.

  2. January 3 · save an update

    The next city will be Paris.

    The move takes effect on January 10.

  3. January 5 · ask a query

    What is the current city?

    The correct answer is Berlin. The move is still in the future.

Original rule → Paris
It chooses the most recently recorded fact.

Date-aware rule → Berlin
It selects the fact valid on the requested date.

A fourth action asks on January 12, when Paris is correct. These four actions are events. Together they form one scenario: a complete test story. Fixing the earlier answer must preserve the later one.

See the JSON fields behind this example

Two complete events from future-move: the Paris update and the January 5 query. tenant: north and user: ada identify the owner. entity: account names the subject; key: city names its property.

at is the arrival date; valid_from is when the fact takes effect; as_of is the date the question asks about. Confidence is an authored input score, not a model probability. expected and should_retain are scoring labels that the fixed memory program ignores.

Four versions of the memory rules

A policy decides which facts to keep and which ones to retrieve. A candidate is a proposed policy change. Python tested each version on the same 20 scenarios.

Baseline 13/20 pass
The original rules: prefer recent matching facts without checking their subject or validity date.
Scoped history 19/20 pass
Changes the baseline to select the requested subject and date. This fixes the early Paris answer.
Deduplicate confirmations 19/20 pass
Starts from Scoped history. Three confirmations of language = German use one stored record instead of three, with the same answer.
Write more 16/20 pass
Also starts from Scoped history. It lowers the threshold from 0.7 to 0.2. A speculative delivery = courier scored 0.4 replaces confirmed pickup and makes the answer wrong.

“Parent” means the version a change starts from. The last two policies are separate branches from Scoped history. These counts describe the supplied frozen experiment, not real-world accuracy. A coding assistant drafted these policies with access to all the scenarios; human approval is still pending.

We compare correct answers, memory use, and fixed safety checks. A scenario passes only if every answer is correct and every check passes. A violation is a failed check for owner isolation, deleted records, or prohibited writes. All four policies pass those checks here; their answer quality differs.

Confidence controls whether a proposed fact is stored. The test supplies the score; the program does not estimate it. A delivery = courier proposal scored 0.4 is rejected at the usual 0.7 threshold, but stored by Write more at 0.2. These scores are not measured probabilities of correctness.

What runs here, and why does the contract say eight?

Each of the four configurations runs the same 20 test stories. Each story starts with empty memory and runs once: 4 configurations × 20 stories = 80 scenario-runs. The Python rules are deterministic. Running the same story again would add no evidence about answer quality.

candidates.json lists the four configurations. contract.json sets maximum limits: eight configurations including the baseline, 64 stories per configuration, 64 events per story, and 30 seconds for evaluation. These are ceilings for additional experiments, not the counts used here. There are no hidden candidates.

Python runs the saved settings. No LLM generates the tests, proposes new settings, answers questions, or scores results during these runs.

04 / Recommendation and human review

Has anyone approved this change?

A rule produces an accept or reject recommendation from the results. A person still has to review it; a recommendation does not deploy anything.

Hard constraints

These are checks that must pass: keep users' and workspaces' data separate, remove deleted memory records, and reject writes with a disallowed key, source, or kind. A violation is one failed check.

A better score cannot override a failed hard constraint. These checks cover only this fixture suite.

03 / Whole-experiment evidence

What improved, and what did it cost?

Every value below is computed by Python and read from the bundle. Repeated synthetic runs measure this experiment; they do not establish real-world reliability.

Policy recommendations compare with the candidate's parent. The original baseline traces remain visible below.

How to read success, memory use, time, and violations
Downstream success
A scenario passes only when every answer is correct and every implemented hard-constraint check passes. 19/20 means 19 complete scenarios pass, not 19 individual answers.
Writes
Precision asks how much of what was kept was useful. Recall asks how much of the useful input was kept. The fixtures label which facts are useful.
Retrieval
Relevant-memory recall checks whether retrieval found the needed fact. Distracting-memory rate counts retrieved records that do not match the expected value, subject, or date.
Context and storage
Context words measure the facts packed for a query, using word counts rather than model tokens. Stored records and bytes measure the saved memory at the end of each scenario.
Local time
p50 is the median scenario duration; p95 marks the slower end of the recorded durations. These are noisy local Python timings, not model response times.
Violations
A failed isolation, deletion, or prohibited-write check. Zero means the implemented checks passed on these fixtures; it is not a general security guarantee.
